协议背景见 [`docs/04-ESP32-CAN电机驱动.md`](../docs/04-ESP32-CAN电机驱动.md)，

## 一、相位 1~7（2026-09-20，自检固件）

分相位验，每相位只验一件事。**全通之后**才把已验证的代码抽成
`firmware/esp32_turret/main/motor_twai.c`。

| 相位 | 验什么 | 接线 | 判据 | 实测结果 |
|---|---|---|---|---|
| 1 | 片内回环 | 不接线 | 收到自己发的帧，错误计数 0 | 15 收 / 0 错 |
| 2 | GPIO4→GPIO5 跨引脚通路 | 杜邦线 GPIO4↔GPIO5 | **不能拿"收到帧"当判据**（CAN 节点不收自己发的帧），要看 `tx_err/rx_err=0` | 发出去的位都读回来，零错误 |
| 3 | 真总线发 `0x36` 读位置 | 收发器 + 1 号电机 | 应答 `36 + 符号 + 位置4B + 6B` | 1 号 **+30.042°**，连读 3 次一致 |
| 4 | 位置模式点位控制 | 同上 | 6 段 30° 往返，方向全对、净残差小 | 净位移 **−0.686°** |
| 5 | 参数写诊断 | 同上 | 写成功的应答形状 | 6 条变体全回 `00 EE`（见"已知遗留"） |
| 6 | 差速 + 2 号镜像补偿 | 两台电机 | 纯俯仰 / 纯自转时两个世界角的解耦度 | 纯俯仰 Δ俯仰 **+10.34°** / Δ自转 +0.30°；纯自转反之 |
| 7 | **速度模式差速逆解** | 两台电机 | 同上，但走 `F6` + `snF=0` 立即执行 | 纯俯仰俯仰 **+36.62°/s** / 自转 +0.33°/s；纯自转俯仰 −0.61°/s / 自转 **+37.29°/s** |

### 为什么相位 6 和 7 是两条独立证据

| | 相位 6（位置模式） | 相位 7（速度模式） |
|---|---|---|
| 触发方式 | `FF 66` 多机同步广播（缓存多台、同一刻触发） | `snF=0` 立即执行 |
| 读回方式 | 停稳后读 `0x36` 位置 | 边转边读 `FD` 转速 |

两条路径的**符号组逐条对上**，才敢说差速逆解写对了。
单靠一条证据无法排除"符号对但幅度靠巧合"。

### 相位 7 的符号基准

```
cmd1 =  ω_tilt + ω_pan
cmd2 =  ω_pan  − ω_tilt      /* 2 号镜像安装 ⇒ 相当于取反 ω_w2 */
```

| 指令 | cmd1 | cmd2 |
|---|---|---|
| 纯俯仰 | +V | −V |
| 纯自转 | +V | +V |

## 二、M2e 上板（2026-09-21）

把 `ω_ref` 从"PC 上位机灌进去的假值"换成"手柄摇杆真值"，**整条链路首次闭环**：

```
摇杆 ──► BLE notify ──► ω_ref ──► 差速逆解 ──► CAN ──► 两台电机
        （M2a/M2b）   （M2c）      （相位 7）    （相位 1~3）
```

**结论**：用户上板操作确认「**能控制的转动了**」—— 手柄摇杆驱动转台正常，
松手即停，方向符合预期。

### 串口日志关键行（实测抄录）

```
[motor] TWAI 就绪：tx=GPIO4 rx=GPIO5 500 kbps
[motor] 1 号 +28.690   2 号 -10.321
[motor] 初始姿态: 俯仰=+19.505 度  自转=+9.184 度
```

这三行分别证明：

| 日志 | 证明了什么 |
|---|---|
| `TWAI 就绪` | 节点建起来了，引脚没撞 console UART（GPIO43/44） |
| `1 号 / 2 号` 都有读数 | 两台地址都对、总线通、`0x36` 请求**没有**踩双校验的坑 |
| `初始姿态` | `motor_read_pose()` 的两轮读 + 逆解都对，且 2 号镜像补偿方向正确 |

> ⚠ 说明：这里抄的是**关键行**，不是完整 dump（当次没有存全量日志）。
> 判据性的三行都在上面，缺的只是 NimBLE 侧的启动噪声。

### 仍未钉死的一项

`OMEGA_MAX_DPS = 60 °/s` 是**估计值**，以及各轴符号与机构正方向的对齐。
上板觉得手感不对再调 —— 符号要反只需把某个轴取负，**不用改结构**。

## 三、已知遗留：位置到达窗口是死命令

`D1 07 <store> <窗口2B>`（改位置到达窗口）在本机电机固件 **V2.0.4 上是死命令**。

穷尽过的证据：**6 条形状变体全部回 `00 EE`**，其中包含

- 「把当前值 0.8 原样写回」
- 「去掉辅助码」

⇒ 排除取值不在允许集、排除辅助码写错。
同族指令 `D3 56`（改过热过流）回 `02 执行正确`，说明**写机制本身是好的**。
唯一办法是用电机自己的 OLED 菜单改 `PRWindow`。

**影响面**：只限位置模式的收尾残差（到位判据 = `|目标−实际| < 窗口`，
默认 0.8° ⇒ 冲过 ~0.5° 就宣布到位）。**增稳主线走速度模式，压根没有到位窗口
⇒ 不阻塞主线。**

## 四、复现

上位机侧的复现命令见 [`README.md`](README.md)「复现」一节。
ESP32 侧的复现是：把 `firmware/esp32_turret/` 拷到**纯英文路径**再编译烧录
（中文路径下工具链会崩，见 [`firmware/README.md`](../firmware/README.md)），
然后看串口有没有上面那三行 `[motor]` 日志。

相位 1~7 是**分阶段自检固件**，不在本仓库里（那是过程产物）；
其已验证的部分已经以 `motor_twai.c` 的形式落到固件中，
每个函数对应的相位在 [`docs/04`](../docs/04-ESP32-CAN电机驱动.md) §12 有对照表。
