# 汇电籽-601 串口陀螺仪模块 —— 协议整理

> **这份文档是什么**：把厂商的《汇电籽-601 模块通信协议说明书》整理成**可以直接照着写固件**的规格。
> 与逆向工程里那份 Emm_V5 协议笔记同一性质 —— 都是"能落成代码"的协议层。
>
> **硬件**：汇电籽-601 串口陀螺仪模块（板载 ICM42688 六轴 + TI M0 单片机）
> **接口**：UART，**固定 115200 8N1**，无校验位，小端
> **上报率**：**固定 100 Hz**，协议里没有改速率的指令
> **供电**：**4.5–5.5 V（要 5 V，不是 3.3 V）**；逻辑电平 3.3 V，UART 线可直连 ESP32

---

## 0. 为什么会有这份笔记

v1.1 的总体方案把 IMU 当成一颗**裸的 ICM-42688-P 走 SPI** 来设计，
直到拿到实物才发现它是一个**串口模块**：器件本身确实是 ICM42688，
但外面包了一颗板载 M0 —— 接口、采样率、供电全都和假设不同。

这件事本身是个教训：**"芯片型号"不等于"你要面对的东西"**。
模型/方案再漂亮，第一步永远该是先确认手上实物到底长什么样。

协议内容来自厂商 PDF，本笔记**不复述原文的排版**，而是按"写代码需要什么"重排：
帧结构 → 校验 → 指令 → 上报解析 → 换算 → 可直接跑的参考实现。

## 1. 帧格式

所有下行指令和上行数据用**同一种帧**：

```
┌──────┬──────┬────────┬──────┬─────┬─────────┬──────┐
│ 0xAA │ 0x55 │ DevID  │ CMD  │ LEN │  DATA…  │  CS  │
│  1B  │  1B  │  1B    │  1B  │ 1B  │  LEN B  │  1B  │
└──────┴──────┴────────┴──────┴─────┴─────────┴──────┘
  帧头1   帧头2    设备ID   指令码  长度    数据区   校验和
```

- **帧头**固定 `0xAA 0x55`
- **DevID** 默认 `0x60`（十进制 96）。`0xFF` 是广播地址，**不能**当设备 ID 用
- **LEN** 是**数据区**的字节数，不含帧头/DevID/CMD/LEN/CS
- **小端**：多字节字段低字节在前

### 校验和

计算范围是**从 DevID 到 DATA 结束**（不含两个帧头字节，也不含 CS 自己）：

```python
cs = (dev_id + cmd + length + sum(data)) & 0xFF
```

> ⚠ **注意不含 0xAA/0x55**。这是最容易写错的一处 ——
> 如果照抄"所有字节求和"会把帧头也算进去，得到的帧虽然自洽但模块不认。

**手算验证**（用厂商文档给的例子）：

| 帧 | 计算 | CS |
|---|---|---|
| `AA 55 60 0A 01 01 6C`（启动上报） | 96+10+1+1 = 108 | `0x6C` ✅ |
| `AA 55 60 10 00 70`（重新校准） | 96+16+0 = 112 | `0x70` ✅ |
| `AA 55 60 12 00 72`（软复位） | 96+18+0 = 114 | `0x72` ✅ |

## 2. 指令表（下行，ESP32 → 模块）

| CMD | 名称 | LEN | DATA | 说明 |
|---|---|---|---|---|
| `0x0A` | 启动/停止上报 | `0x01` | `0x01`=启动，`0x00`=停止 | **必须发这条模块才开始推数据** |
| `0x0B` | 设置上报模式 | `0x01` | `0x00`=全数据，`0x01`=仅姿态 | 本项目用 `0x00` |
| `0x10` | 触发重新校准 | `0x00` | — | 模块静止时触发 |
| `0x12` | 软复位 MCU | `0x00` | — | 发送后串口可能短暂断开 |
| `0x14` | Yaw 单圈比例校准 | `0x04` | float32（小端）实际测得角度 | 修正 Yaw 转一圈 ≠ 360° 的累计误差 |
| `0xF0` | 通用应答 ACK | 可变 | 见下 | **模块 → ESP32**，用于确认下行指令 |

### 0xF0 应答格式

```
DATA[0] = 被应答的指令码，后续字节为附加信息
例：AA 55 60 F0 01 0A 5B     → 成功接收并执行了 0x0A
```

> ⚠ **`0x0A` 和 `0x0B` 是两条指令，别只发一条。**
> `0x0B` 只是设模式，**模块仍然不会推数据**；必须再发 `0x0A 01 01` 启动上报。
> 正确顺序：**先 `0x0B` 设模式，再 `0x0A` 启动**，每条都等 `0xF0` 应答。

## 3. 上报数据（上行，模块 → ESP32）

模块按 **100 Hz** 主动推送，帧的 CMD 固定为 **`0x01`**。

### 模式 0：全数据，`LEN = 18`（本项目使用）

```
[ AccX, AccY, AccZ, GyroX, GyroY, GyroZ, Pitch, Roll, Yaw ]
   6 × int16 原始值（小端，各 2 B = 12 B）      3 × 姿态角（各 2 B = 6 B）
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `AccX/Y/Z` | int16 | 加速度计原始值 |
| `GyroX/Y/Z` | int16 | **陀螺原始值 —— 增稳环要的就是这三个** |
| `Pitch` / `Roll` | int16 | 有符号，范围 −180.00° ~ +180.00° |
| `Yaw` | **uint16** | 无符号，范围 0.00° ~ 360.00° |

### 模式 1：仅姿态，`LEN = 6`

```
[ Yaw, Pitch, Roll ]     ← 注意 Yaw 在第一位，与模式 0 的顺序不同
```

### 姿态角换算

角度是**放大 100 倍的整数**（为了省带宽）：

```
真实角度(度) = 整型上报值 / 100.0
```

> ⚠ **`Yaw` 是 uint16，`Pitch`/`Roll` 是 int16**。
> 如果三个都用同一个 `int16` 去解，**Yaw 在 180°~360° 区间会出现负数**。
> 这是第二个容易踩的坑。

### ⚠ 关于陀螺原始值

厂商文档**没有给出** `GyroX/Y/Z` 的**量程（灵敏度，LSB/(°/s)）**。
所以拿到原始值后**无法算出物理角速度**，必须实测标定：

1. 让模块**绕某一轴以已知角速度匀速转**（例如用转台或匀速手动旋转并计时）
2. 记录该轴上 `Gyro` 原始值的变化量
3. `LSB_per_dps = Δ原始值 / Δ角速度`

**这项标定是 M6 的必做项**（详见总体方案 Q-27 / R-22）——
没有它，增稳环的增益 `Kv` 就没有物理含义，只能靠试凑。

## 4. 上电初始化时序

```
① 发 0x0B  DATA=0x00（全数据模式）  → 等 ACK(0xF0)，超时 100 ms 重试，共 3 次
② 发 0x0A  DATA=0x01（启动上报）    → 等 ACK(0xF0)，同样重试
③ 模块开始 100 Hz 推送 0x01 帧，主机校验帧头/LEN/CS
④ 静止 2 s 采均值 → 零偏残差超限则发 0x10 重新校准
⑤ 进入闭环，收帧事件驱动 imu_task
```

**两个时序要点**：

- **模块是主动上报的，不需要主机轮询**。主机发读命令只会打乱它的节奏，
  千万别在正常运行时去"读一帧"。
- **丢帧不会重发** —— 这是和 SPI 轮询最本质的区别：SPI 读到坏数据可以重读一次，
  串口推过来的帧丢了就是丢了。所以**帧超时检测与校验和连续错误计数是必需的**，
  不能只做"校验不过就丢弃"（那样会静默地一直用旧数据闭环）。

## 5. 参考实现（含帧级自检）

直接用 Python 描述协议，**自检部分把每一帧与厂商文档里的例子逐字节断言** ——
不接硬件就能验证协议理解是否正确：

```python
import struct

DEV_ID = 0x60
HEAD = b"\xAA\x55"


def build(cmd: int, data: bytes = b"", dev: int = DEV_ID) -> bytes:
    body = bytes([dev, cmd, len(data)]) + data
    return HEAD + body + bytes([sum(body) & 0xFF])


def parse(frame: bytes):
    if len(frame) < 7 or frame[:2] != HEAD:
        return None
    dev, cmd, length = frame[2], frame[3], frame[4]
    if len(frame) != 5 + length + 1:
        return None
    body, cs = frame[2:-1], frame[-1]
    if sum(body) & 0xFF != cs:
        return None
    return dev, cmd, frame[5:-1]


def parse_report(payload: bytes):
    """解析 0x01 上报帧的数据区，返回物理量"""
    if len(payload) == 18:
        # 6 个 int16 原始值 + Pitch/Roll(int16) + Yaw(uint16)
        ax, ay, az, gx, gy, gz, pitch, roll, yaw = struct.unpack("<6h2hH", payload)
        return dict(acc=(ax, ay, az), gyro_raw=(gx, gy, gz),
                    pitch=pitch / 100.0, roll=roll / 100.0, yaw=yaw / 100.0)
    if len(payload) == 6:
        # 模式 1 的顺序是 [Yaw, Pitch, Roll]，且 Yaw 是 uint16
        yaw, pitch, roll = struct.unpack("<H2h", payload)
        return dict(yaw=yaw / 100.0, pitch=pitch / 100.0, roll=roll / 100.0)
    return None


# ---- 指令构造 ----
CMD_SET_MODE   = lambda mode: build(0x0B, bytes([mode]))   # 0=全数据 1=仅姿态
CMD_REPORT     = lambda on:   build(0x0A, bytes([1 if on else 0]))
CMD_CALIB      = build(0x10)
CMD_RESET      = build(0x12)
CMD_YAW_SCALE  = lambda deg:  build(0x14, struct.pack("<f", deg))


if __name__ == "__main__":
    # 逐条对照厂商文档给的示例帧（这是本文件的核心价值）
    assert CMD_REPORT(True).hex(" ").upper() == "AA 55 60 0A 01 01 6C"
    assert CMD_REPORT(False).hex(" ").upper() == "AA 55 60 0A 01 00 6B"
    assert CMD_SET_MODE(0).hex(" ").upper() == "AA 55 60 0B 01 00 6C"
    assert CMD_SET_MODE(1).hex(" ").upper() == "AA 55 60 0B 01 01 6D"
    assert CMD_CALIB.hex(" ").upper() == "AA 55 60 10 00 70"
    assert CMD_RESET.hex(" ").upper() == "AA 55 60 12 00 72"
    assert CMD_YAW_SCALE(360.0).hex(" ").upper() == "AA 55 60 14 04 00 00 B4 43 6F"

    # 解析反向验证
    assert parse(bytes.fromhex("AA5560F0010A5B")) == (0x60, 0xF0, b"\x0A")
    assert parse(bytes.fromhex("AA55600A01016C")) == (0x60, 0x0A, b"\x01")
    # 坏校验应被拒
    assert parse(bytes.fromhex("AA55600A010100")) is None

    # Yaw 跨 180° 的解析（uint16 不能当 int16 解），Pitch/Roll 为负
    pkt = struct.pack("<6h2hH", 0, 0, 0, 0, 0, 0, 100, -100, 27000)
    r = parse_report(pkt)
    assert abs(r["yaw"] - 270.0) < 1e-6, r
    assert abs(r["pitch"] - 1.0) < 1e-6, r
    assert abs(r["roll"] + 1.0) < 1e-6, r

    # 模式 1：Yaw 在第一位且为 uint16
    r1 = parse_report(struct.pack("<H2h", 35950, -450, 1234))
    assert abs(r1["yaw"] - 359.5) < 1e-6, r1
    assert abs(r1["pitch"] + 4.5) < 1e-6, r1

    print("全部自检通过：协议理解与厂商文档一致")
```

**这段自检的意义**：本项目的协议结论**不依赖硬件就能被验证**。
换了固件版本或换了一颗模块，先跑这个脚本，
能立刻区分"是我代码写错了"还是"模块行为变了"。

## 6. 接线与调试

| 模块引脚 | 接到 ESP32 | 说明 |
|---|---|---|
| `V` | **5 V** | ⚠ **不是 3.3 V**，规格 4.5–5.5 V |
| `G` | GND | 与 ESP32 共地 |
| `T`（模块 TX） | **GPIO18（UART1_RX）** | **交叉接** |
| `R`（模块 RX） | **GPIO17（UART1_TX）** | **交叉接** |

**排查顺序（比 CAN 简单，因为模块是主动推的）**：

1. **上电后什么都不发，先看有没有数据流。** 模块只要上电并已启动上报就会推帧；
   一个字节都没有 → 先查 TX/RX 是否交叉、5 V 是否到位，**不是波特率问题**（波特率固定）
2. 有数据但全是乱码 → 波特率/数据位不对（应为 115200 8N1），或地没接好
3. 有合法的 `AA 55` 但不是 `0x01` → 可能收到 `0xF0` 应答，说明上电初始化指令已执行
4. 帧头对、校验错 → 线缆干扰；缩短线、`5V`/`GND` 成对走线
5. **注意模块要上电后手动发 `0x0A` 才会开始上报** —— 如果没发过，
   它可能安静地什么都不推，看起来像"模块坏了"

## 7. 已知未知项

| 项目 | 状态 | 影响 |
|---|---|---|
| 陀螺量程 / 噪声密度 | ⬜ 厂商文档未给 | 无法把原始值换算成 °/s，必须实测标定；影响 SR-10 的超量程判据 |
| 内部是否做抗混叠滤波、截止频率、群延迟 | ⬜ 未公开 | 直接决定稳定环还剩多少相位裕度，是**黑盒**，必须靠扫频实测反推 |
| 回报率能否改到 > 100 Hz | ⬜ 待验证（厂商有 `校准工具.exe` GUI） | 若能改，增稳带宽上限直接抬升，R-21 消失 |
| 姿态角内部的融合算法 | ⬜ 未公开 | 本方案**不用姿态角做速率反馈**（延迟大），只用它做漂移监测，影响有限 |

> 这几项里**"内部滤波群延迟"最关键** —— 它是唯一一个
> 会直接影响闭环稳定性的未知量，且无法从文档获得。

## 8. 速查

```
帧:      AA 55 | DevID | CMD | LEN | DATA | CS      CS = (DevID+CMD+LEN+ΣDATA) & 0xFF
DevID:   0x60（默认），0xFF 为广播
初始化:  AA 55 60 0B 01 00 6C   → 设为全数据模式
         AA 55 60 0A 01 01 6C   → 启动 100 Hz 上报
校准:    AA 55 60 10 00 70       → 静止时触发
复位:    AA 55 60 12 00 72       → 软复位
上报帧:  CMD=0x01, LEN=18
         [AccX,Y,Z, GyroX,Y,Z (6×int16), Pitch,Roll (int16), Yaw (uint16)]
         角度 = 整型值 / 100.0
```
