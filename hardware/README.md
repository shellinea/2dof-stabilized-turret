### ⚠️ CAN 收发器采购要点

ESP32-S3 芯片内部有 **TWAI**（CAN 2.0 控制器），但只输出逻辑电平 TX/RX，
**必须外接收发器芯片**才能接上电机总线。现有的 `ZDT_CANable` 是 **USB 适配器**，
插不到 ESP32 上。

- ✅ **SN65HVD230** 首选；**TJA1051T/3** 亦可
- ❌ **不要买 MCP2551** —— 5 V 供电，与 ESP32 电平不兼容，还得额外做电平转换
- 优先选**板载 120 Ω 终端电阻**的模块（视总线拓扑决定是否启用）

## 引脚分配

| 功能 | 引脚 | 说明 |
|---|---|---|
| TWAI_TX | GPIO4 | → CAN 收发器 TXD |
| TWAI_RX | GPIO5 | ← CAN 收发器 RXD |
| IMU UART1_TX | GPIO17 | → 汇电籽-601 的 `R`（模块 RX） |
| IMU UART1_RX | GPIO18 | ← 汇电籽-601 的 `T`（模块 TX，100 Hz 上报） |
| UART2_TX | GPIO10 | → 泰山派 RX（二期，**引脚待上板确认**） |
| UART2_RX | GPIO11 | ← 泰山派 TX（二期，**引脚待上板确认**） |
| 备用 | GPIO12 / 13 / 14 | 原 IMU SPI 引脚已全部释放，空出备用 |
| 板载 RGB (WS2812) | GPIO48 | 状态指示，无需接线 |
| 板载 BOOT 按键 | GPIO0 | 本地急停 / 模式切换备用 |
| UART0 | GPIO43/44 | 调试日志，保留 |

> **IMU 改用 UART1（GPIO17/18）**：汇电籽-601 是**主动上报**的串口模块，
> 上电就按固定 100 Hz 推帧，主机只管收，不需要 SPI 那种"主机发起读时序"的调度。
> 于是原来的 IMU SPI 引脚 **GPIO10–14 全部释放**，其中 **GPIO12/13/14 留作备用**，
> **GPIO10/11 挪给二期泰山派链路（UART2）**——具体引脚上板前用原理图确认。

### 必须避开的引脚

| 引脚 | 原因 |
|---|---|
| **GPIO26–32** | 板载 Flash / PSRAM 专用，**不可用作普通 IO**，否则系统崩溃 |
| **GPIO33–37** | 8 MB **Octal PSRAM** 可能额外占用（厂商文档只列了 26–32）。**上板前用万用表/原理图确认**，本项目已避开 |
| GPIO19 / 20 | 原生 USB（启用 USB CDC 时被占用） |
| GPIO0 / 45 / 46 | strapping 引脚 |
| GPIO8–15 / 45 / 46 | ADC2，WiFi/BLE 开启时不可用（本项目不用 ADC） |

## 供电方案：12 V 电池

X42S 供电范围 **10–29 V**（标准版），12 V 可行。但电池类型要挑：

| 电池类型 | 电压区间 | 结论 |
|---|---|---|
| 3S LiPo | 满 12.6 V → 放空 9.0 V | ⚠ **必须限制放电深度**，放到 9 V 会低于电机 10 V 下限触发低压保护。建议截止 3.5 V/cell（≈10.5 V） |
| **4S LiFePO4** | 10.0 → 14.6 V（标称 12.8 V） | ✅ **最合适** |
| 铅酸 12 V | 放空 10.5 V → 浮充 13.8 V | ✅ 可用，但重、放电倍率低 |

**12 V 相比 24 V 的两个影响**：

1. **高速扭矩下降** —— 供电电压越低，高速时电流爬升越慢、扭矩衰减越早。
   本项目是低速低负载工况，影响可忽略；**但对增稳环要留意**：
   增稳要在扰动瞬间快速反向纠偏，对瞬时扭矩有要求。
   若发现增稳响应"发软"，优先怀疑 12 V 下的扭矩不足。
2. **电流翻倍** —— 同功率下 12 V 电流是 24 V 的 2 倍，电池放电能力要匹配。

> **电流不用估算，直接测**：`python tools/zdt_can.py status` 会读回总线电压与相电流。
> 让转台跑起来（尤其增稳环频繁纠偏时）看实际电流。

## CAN 总线接线要点

- **CAN_H / CAN_L 不能接反**（接反是最常见的"扫不到设备"原因之一）
- **两端各一个 120 Ω 终端电阻**，总线长度尽量短
- **必须共地** —— 电机电源地与 ESP32 地要连
- 波特率 **500 kbps**，扩展帧，`ID = (地址 << 8) | 包号`

### 现场排查的根因优先级

历史排查证明，"读不到数据"的根因按这个顺序找：

1. 电机小屏不显示 + 蓝灯常亮 → 固件卡 bootloader → 重刷
2. 接线松紧 / 接触不良 → 重插压紧
3. **地址重复**
4. `P_Serial` 参数必须 = `CAN1-MAP`
5. CAN_H / CAN_L 接反
6. 共地 + 120 Ω 终端电阻

> 在官方 GUI 里遇到的"地址 2 无数据返回"是 **GUI 侧的问题**，
> 不是硬件或地址问题——`python tools/zdt_can.py --addr 1,2 scan` 实测两台都在线。
> 详见 [`docs/01-CAN调试入门指南.md`](../docs/01-CAN调试入门指南.md)。

## IMU 布线要点

汇电籽-601 模块 **装在托盘（载荷）上**（31 × 28.4 mm，安装孔距 24 × 22 mm），
随载荷一起运动——这样测到的姿态不含机构柔性误差。
代价是 **UART 线要跨转动关节**：

- **4 线而非 6 线**：`V(5V) / T(模块 TX → ESP32 RX) / R(模块 RX → ESP32 TX) / G(GND)`，
  比原来的 SPI 方案少 2 根，跨关节的柔性线束更好布置、更不容易断
- **供电是 5 V 不是 3.3 V**：模块要 4.5–5.5 V，直接接板上 5 V 轨
  （12 V→5 V DC-DC 已有）；**逻辑电平是 3.3 V，UART 线可直连 ESP32，不需要电平转换**
- **模块主动上报，主机不用轮询**：上电即按固定 **100 Hz** 推帧
  （串口固定 115200 / 8 数据位 / 1 停止位 / 无校验，小端；协议里没有改速率的指令），
  ESP32 侧是"收帧触发"的事件驱动。采样时刻由模块决定、帧间隔稳定，
  省掉了 SPI 主机发起读时序的调度不确定性，**相位滞后确定**
- **上报指令 `0x01` 选全数据模式（`LEN=18`）**：`AccX/Y/Z`、`GyroX/Y/Z` 六个 int16 原始值
  加 `Pitch/Roll/Yaw` 姿态角；仅姿态模式是 `LEN=6`（`Yaw/Pitch/Roll`），
  **但增稳环要的是陀螺**，所以必须用全数据。角度都是 ×100 的整数
- 一期用**限位自转 ±90°** 规避绕线问题
- 必须有**掉线检测**：帧超时 + 校验和错误计数（帧格式 `AA 55 <DevID> <CMD> <LEN> <DATA…> <CS>`，
  `CS = (DevID + CMD + LEN + ΣDATA) & 0xFF`，默认设备 ID `0x60`）超阈值时自动旁路稳定环
  （否则会拿错误数据去纠偏）
- 模块内部**已做姿态融合**，直接输出 Pitch/Roll/Yaw，ESP32 不需要自己做姿态解算；
  水平静止时可用校准指令 `0x10` 触发重新校准
- ⚠ **上电要发两条指令**：`0x0B` 设全数据模式，**再发 `0x0A` 启动上报** ——
  只发 `0x0B` 模块不会推数据，现象是"一个字节都没有"，很容易误判成线接错了
- ⚠ **陀螺原始值的灵敏度（LSB/(°/s)）厂商没给**，不标定就没法把 `GyroX/Y/Z`
  换算成 °/s，稳定环增益也就没有物理含义 —— M6 必须实测标定

> 完整的帧结构、全部指令、换算公式与**带自检的参考实现**见
> [`docs/02-601串口陀螺仪协议.md`](../docs/02-601串口陀螺仪协议.md)。
